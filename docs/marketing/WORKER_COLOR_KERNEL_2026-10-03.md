# Worker color conversion core — October 3, 2026

Status: local executable proof only. Not imported into the private draft handler or production routes. No new deployment, source attachment, publication, customer messages, paid service, credentials or production binding. Existing direct-session engineering authorization covers this work.

## What changed

Pinned lcms-wasm 1.0.5 in the isolated prototype. RGB ICC pixels are converted to an explicit sRGB destination using relative-colorimetric intent and 4,096-pixel batches. Profiles are bounded to 64 KiB; input pixels are bounded to four million; tag data must begin after the tag table. Native profile-open/color-space/transform creation must succeed. No silent assumed-sRGB fallback exists for an invalid supplied profile. Native transform/profile handles close independently. Explicitly owned native pixel buffers replace the upstream convenience wrapper, which only freed them on its successful path. A runtime/transform failure poisons reuse; cleanup failure is observable instead of returning a silent success. Alpha is not processed by this RGB-only core.

The ordinary upstream loader refused workerd as an unrecognized environment. A build-only adapter verifies the exact upstream loader SHA-256 before changing two environment checks to allow the caller-supplied compiled-module initialization hook. It does not spoof browser globals, fetch code, enable Node compatibility or compile WASM at runtime. The proof statically supplies a CompiledWasm module and sets a non-fetching locateFile label. The untouched native module is 315,910 bytes, SHA-256 dbcbee3fb3a49459a60bb6b29d6ab25fe7c219b0cc0c2b9579c0cc78f7390ddd. The loader source hash is recorded in color-loader-build.cjs; unreviewed changes refuse the adapter.

## Evidence and limits

Known patches were actually encoded with an embedded P3 profile. The test removes iCCP solely to decode the stored profile-space pixel values, then converts those values using the original extracted profile. The independent reference converts the still-profiled PNG to sRGB with native Sharp/lcms. The WASM output matches within two 8-bit channel values and differs from simply stripping the profile. The sRGB case stays within one rounding value. Chunk order/determinism, structural refusals, loader hash changes and injected native trap/cleanup behavior are tested. Agent source review confirmed the corrected patch reference and identified cleanup/bounds issues; root repaired and reran targeted tests.

Actual local workerd performs nine successful conversions and one malformed refusal, with a subsequent successful request and zero outbound calls. Its observed linear memory is 16 MiB. A constant linear-memory size is only a high-water observation: it does not prove freed heap allocations, peak/combined JS/WASM memory, deployed CPU or sufficient production budget. The endpoint exists only in the synthetic test bundle; do not expose it.

Evidence resides under evidence/worker-color-kernel-2026-10-03. The final full prototype suite passed 186 of 187 tests, with zero failures and one explicit Node-native base64 skip. Seven targeted kernel tests passed; targeted lint passed with zero errors. These results are recorded separately. Source files are color-kernel.mjs, color-loader-build.cjs, color-kernel.test.mjs and color-kernel-workerd.test.cjs. Existing source-color-admission continues to refuse ICC photos in the current private handler; this core does not yet establish a normalized image or provenance receipt.
